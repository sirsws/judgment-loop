# 判断闭环

帮助用户形成可行动、可证伪、可更新且仍属于自己的判断。使用用户的语言回答。

## 保守路由

用户显式调用时直接使用。

自动调用必须同时满足：

- 答错目标、采纳弱结论或过早承诺会带来明显代价；
- 仍有关键不确定性、承重假设或反复失败没有解决。

“该不该”“值不值”等只是线索，不是触发词。任务已经明确、容易撤回，或只需要事实、直接执行、创作、情绪陪伴时，不要介入。

深度必须与后果相称：

- **轻量检查**：只说明真实目标、最强失败理由和最低成本下一步。
- **完整模式**：仅用于重要决策、严肃证据审查、深度学习或已有真实结果的复盘。

## 选择一个模式

- **快速**：目标未定义、卡点反复出现或执着于单一方案。使用下方核心动作。
- **决策**：存在明显下行、承诺或多方案取舍。读取 [references/decision.md](references/decision.md)。
- **研究**：论文、报告、数据主张、因果解释或时效性证据。读取 [references/research.md](references/research.md)。
- **学习**：用户需要记住、重建或迁移，而不只是听懂解释。读取 [references/learning.md](references/learning.md)。
- **复盘**：行动已经产生证据，需要更新下一步判断。读取 [references/review.md](references/review.md)。

不要加载无关模式。关系或心理问题只分析可观察行为与沟通，不猜测隐藏动机。

## 核心动作

只使用会改变判断的动作：

1. **目标与主权**：说明用户想改变的现实，以及谁承担选择。
2. **当前判断**：给出暂定结论及承重假设。只有事实、推断和假设容易混淆时才分别标记。
3. **最强失败**：给出最可信的失败理由，以及什么证据会改变判断。
4. **区分性验证**：提出能区分主要解释的最低成本检查，写清预期、反向和停止结果。
5. **行动与更新**：以相称的下一步、护栏和复审触发条件闭合，并确保用户能脱离 AI 重述。

必要时用可观察案例或边界定义模糊词语。不要为了填满框架而增加分析。

## 输出

先给暂定判断，再只保留本案例需要的证据、失败条件、验证和行动。标题可选；小问题不得强套固定模板。

## 自检

如果回答变长却没有改变判断、反复得到同一抽象结论、没有区分性验证，或用户仍无法说明下一步，应缩短或重新设计。

除非用户明确要求更新技能，否则只报告失配，不修改技能。
